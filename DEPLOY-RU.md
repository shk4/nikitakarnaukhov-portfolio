# Как разместить сайт на своём сервере

Основа проекта — версия 52 сайта https://nikitakarnaukhov.ru/. В репозитории также есть последняя правка тестовой копии от 13.10.2026: верхняя обложка кейса скрывается в режиме TLDR.

## Сборка из репозитория

Установи Node.js 22.13 или новее, затем из корня проекта выполни:

```sh
npm ci
npm run build
npm run validate:artifact
```

Готовый сайт находится в `dist/client/`; на сервер нужно загрузить содержимое этой папки. Для работы готового сайта Node.js и база данных не нужны. Пример Nginx лежит в `deploy/nginx.conf`, файлы Docker — в `deploy/`.

## Nginx

1. Скопируй всё из `dist/client/` в `/var/www/nikitakarnaukhov/`. Права должны позволять Nginx читать файлы.
2. Используй `deploy/nginx.conf` как конфигурацию сайта. Если сайт уже настроен с HTTPS, сохрани существующие `listen 443`, `ssl_certificate` и `ssl_certificate_key`, а из примера перенеси `root`, `index`, блоки `location` и `error_page` в действующий HTTPS-блок. Не создавай два конкурирующих блока одного домена.
3. Если папка на сервере другая, измени `root` в конфигурации.
4. Проверь конфигурацию и перезагрузи Nginx:

```sh
sudo nginx -t
sudo systemctl reload nginx
```

Пример рассчитан на размещение в корне домена, например `https://nikitakarnaukhov.ru/`, а не в подпапке `/portfolio/`. HTTPS и DNS настраиваются на твоём сервере/у регистратора отдельно. Сам экспорт не меняет текущий сайт или DNS.

## Apache / обычный хостинг

Скопируй содержимое `dist/client/` в корень сайта, включая файл `.htaccess`. Нужны Apache 2.4, `mod_rewrite`, `mod_mime` и разрешённые правила `.htaccess` (`AllowOverride FileInfo Options Indexes` либо эквивалентная настройка хостинга). Если файловый менеджер скрывает файлы с точкой, включи их отображение.

## Docker

Подготовь отдельную папку для сервера: скопируй туда содержимое `deploy/`, затем скопируй `dist/client/` под именем `www/`. В этой папке, рядом с `Dockerfile` и `compose.yaml`, выполни:

```sh
docker compose up -d --build
```

Сайт будет доступен на самом сервере по `http://127.0.0.1:8080/`. Направь на него существующий HTTPS reverse proxy. Если нужен прямой HTTP-доступ извне без прокси, замени в `compose.yaml` порт `127.0.0.1:8080:80` на `80:80`, предварительно убедившись, что порт 80 свободен. HTTPS в этом контейнере не настроен.

## Важные файлы

Не удаляй `.rsc`: они нужны для переходов между страницами без полной перезагрузки и должны отдаваться с `Content-Type: text/x-component`. Запрос `/.rsc` должен открывать `index.rsc`. Это уже предусмотрено в приложенных конфигурациях.

Адреса `/cases/email-personalization` и других кейсов должны открывать соответствующие `.html` без изменения адреса в браузере. Нельзя направлять все неизвестные адреса на главную, как в обычном SPA: в сборке есть отдельная страница для каждого адреса и настоящая 404.

Картинки, видео и шрифты входят в проект. Крупные медиа автоматически восстанавливаются из локальных частей в `media-source/` при сборке. Figma-вставки, которые открываются по кнопке, и внешние ссылки Telegram/Figma требуют доступа к этим внешним сервисам, как на опубликованном сайте.

## После загрузки

Открой главную и любой кейс напрямую по адресу. Проверь «Подробно / TLDR», переход в другой кейс и обратно на главную, обложки и видео. Пример проверки служебного файла:

```sh
curl -I https://nikitakarnaukhov.ru/.rsc
curl -I https://nikitakarnaukhov.ru/cases/email-personalization.rsc
```

Оба ответа должны быть `200` с `Content-Type: text/x-component`. Несуществующая страница должна возвращать `404`.

Сборка всех 74 маршрутов и наличие локальных ресурсов проверены при подготовке репозитория. Запуск контейнера и проверка на твоём сервере отдельно не выполнялись.
